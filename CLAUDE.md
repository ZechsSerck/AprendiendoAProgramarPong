# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A 2D Pong game built in **Unity 6000.6.7f1** (URP 2D renderer, TextMesh Pro for UI). Code comments and UI text are in Spanish. All gameplay code is in `Assets/Scripts/` and compiles into the default `Assembly-CSharp` assembly. There are no asmdefs and no tests yet, though `com.unity.test-framework` is installed.

## Building / running

There is no CLI build script. You open, play and build the project from the Unity Editor (version 6000.6.7f1). The `.csproj`/`.slnx` files are generated by Unity, so don't edit them by hand. For a headless compile check or build, use Unity's batch mode, for example:

```
Unity.exe -batchmode -quit -projectPath . -logFile -
```

The Unity Editor is often open on this project, and batch mode refuses to run while it is. For a quick compile check, `dotnet build Assembly-CSharp.csproj` works, because the csproj references the Editor's DLLs. The csproj lists each `.cs` file explicitly, though, so a new script only gets compiled once Unity has regenerated the csproj.

If tests are added, run them with `-runTests -testPlatform EditMode|PlayMode -testResults results.xml` (leave out `-quit`), and pick a single test with `-testFilter <FullTestName>`.

## Input

The project uses **only the new Input System** (`activeInputHandler: 1`). Scripts poll `Keyboard.current` directly, as in `kb.wKey.isPressed`, and don't use `InputSystem_Actions.inputactions`. Never use the legacy `UnityEngine.Input` API, because it throws at runtime here. Controls:
- Player 1 (left) uses W/S. Player 2 (right) uses Up/Down arrows.
- In the main menu, Esc quits (`SceneChanger`).
- In a match, Esc or P toggles pause (`PauseMenu`).
- On the victory screen, R starts a rematch and Enter or Esc goes to the menu. Input is ignored for the first `inputDelay` seconds.

## Architecture

The game flow is driven by scenes. The build order is in `ProjectSettings/EditorBuildSettings.asset`:

`MainMenu` → `PlayerVSAI` / `PlayerVSPlayer` → `Victory` → rematch (same game scene) or `MainMenu`

- Scenes are loaded **by string name**. The names live in serialized fields of `SceneChanger`, `GameManager` (`victoryScene`), `VictoryScene` and `PauseMenu`, and the rematch uses `GameSession.LastGameScene`. If you rename a scene, update those fields and the build settings.
- **`GameSession`** is a static class that carries state between scenes:
  - the AI difficulty, set by the menu buttons (`PlayVsAIEasy`, `PlayVsAINormal`, `PlayVsAIHard`);
  - the last winner, and whether the winner was the AI;
  - the last game scene, used for the rematch.

  It isn't saved to disk. When you start a game scene straight from the Editor, it falls back to its defaults (Normal, no winner).
- Cross-object references are **serialized fields wired in the Inspector**, written as `[SerializeField] private` (nothing uses `Find` or singletons). Adding or renaming a field means the scenes have to be rewired. `GameManager` and `AI` log an error in `Awake` when a reference is missing.
- **Paddles:**
  - `Paddle` is the abstract base. It owns `speed`, the `Rigidbody2D`, the cached start position, the movement in `FixedUpdate` and `ResetPosition()`.
  - Each subclass only sets `move` (-1, 0 or 1) in `Update`. `Players` reads the keyboard. `AI` follows the ball only when the ball is moving toward it, and otherwise returns to the centre.
  - `AI` takes its speed, dead zone, reaction time and aim error from the `easy`, `normal` or `hard` settings for `GameSession.Difficulty`. Its inherited `speed` field is overwritten in `Awake`.
  - `GameManager.player1` and `player2` are typed as `Paddle`, so either one can be a human or the AI.
- **Scoring loop:**
  1. `Goal` is a trigger with `isLeftGoal`, and only reacts to objects tagged `Ball`. It calls `GameManager.AddScore(1 or 2)`.
  2. `AddScore` updates the score texts and calls `CheckVictory()`.
  3. On a win, `CheckVictory()` records the result in `GameSession` and loads `Victory`, and the round isn't reset. A `gameOver` flag ignores any later goals.
  4. Otherwise `ResetRound()` puts the paddles back and calls `Ball.ResetBall()`. The ball waits `serveDelay` seconds in the centre, showing an optional countdown, then serves.
- **Ball physics:**
  - Every physics step, `Ball` renormalizes its velocity to `currentSpeed` and enforces a minimum horizontal component (`minHorizontal`).
  - On a paddle hit, the exit angle depends on where the ball struck the paddle (up to `maxBounceAngle`), and `currentSpeed` goes up by `speedIncrease`, capped at `maxSpeed`. Every serve resets it to `speed`.
  - `Ball` switches its Rigidbody2D to continuous collision detection in code.
  - Positions are reset through `rb.position`, never through `transform.position`.
- **Pause:** `PauseMenu` sets `Time.timeScale` to 0 and restores it in `OnDestroy`. Gameplay timers use scaled time, so the serve countdown also freezes while the game is paused.

## Editing Unity assets

- Every asset needs its `.meta` file, and the GUIDs in it are what scenes reference. When you move or rename a script, move its `.meta` with it, and keep the class name matching the file name.
- Scenes (`.unity`) are YAML text and can be inspected with grep. Make structural edits in the Editor when you can.

## Reglas de trabajo

- Los comentarios del código van en español, y los métodos en PascalCase.
- No usar la clase `Input` antigua (`Input.GetAxis`); usar `Keyboard.current`.
- No editar archivos `.unity`, `.prefab` ni `.meta` directamente. Si un cambio requiere tocar la escena o el Inspector, dejarlo anotado al final como "pasos manuales" para que yo los haga en el editor.
- Hacer un commit por cada mejora, con un mensaje claro en español.
- No tocar la carpeta `Assets/TextMesh Pro` ni `Assets/Welcome` (vienen de la plantilla de Unity).
- Al terminar, entregar un resumen de lo cambiado y una lista de lo que debo configurar a mano en Unity.
